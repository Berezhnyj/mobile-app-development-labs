# :bookmark_tabs: Лабораторна робота №7
## Тема: "Розроблення та інтеграція платформозалежних плагінів (Native Plugins)"

### 1. Мета роботи
Опанування механізмів взаємодії Flutter-застосунку з нативними платформами (Platform Channels). Набуття навичок написання платформозалежного коду (Android/Kotlin), інкапсуляції цього коду у відокремлений плагін та дистрибуції плагінів через систему контролю версій.

---

### 2. Завдання до лабораторної роботи

**Мета завдання:** Розробити власний Flutter-плагін для управління апаратним ліхтариком пристрою, розмістити його в окремому репозиторії та інтегрувати у ваш основний застосунок як "приховану" (Easter egg) функцію.

**Функціональні вимоги:**
1. **Розробка плагіна (Native Plugin):**
   - Створити окремий Flutter Plugin проєкт.
   - Реалізувати нативну логіку увімкнення/вимкнення ліхтарика **виключно для ОС Android** (через взаємодію з `CameraManager`).
   - Увесь код комунікації (Platform Channels) має бути інкапсульований всередині плагіна. 
2. **Публічний API плагіна:**
   - Плагін повинен експортувати статичний метод для перемикання стану ліхтарика (наприклад, `MyFlashlightPlugin.toggle()`).
3. **Обробка деградації (Graceful Degradation):**
   - Оскільки нативна логіка реалізується лише для Android, плагін повинен вміти визначати поточну платформу.
   - При спробі виклику методу на непідтримуваній платформі (наприклад, iOS або Web), застосунок не повинен падати (`crash`). Замість цього система має елегантно перехопити цю подію та вивести користувачеві діалогове вікно (або SnackBar) з попередженням про відсутність підтримки.
4. **Інтеграція в основний застосунок:**
   - Додати плагін до `pubspec.yaml` основного застосунку не локальним шляхом, а **через посилання на віддалений Git-репозиторій**.
   - Додати в основний застосунок прихований UI-тригер (Easter egg) — наприклад, довге натискання на логотип, свайп або секретна комбінація в профілі, яка вмикатиме ліхтарик.

**Інженерні вимоги (Acceptance Criteria):**
- **Безпека апаратного рівня (Stress Test):** Виклик ліхтарика на пристрої без спалаху (наприклад, на деяких планшетах або емуляторах) не повинен викликати `Exception`. Нативний код має перевіряти наявність апаратної фічі (`PackageManager.FEATURE_CAMERA_FLASH`) та наявність необхідних дозволів у `AndroidManifest.xml`.
- **Ізоляція відповідальності:** Забороняється розміщувати код ініціалізації `MethodChannel` в основному застосунку. Застосунок імпортує лише Dart-інтерфейс плагіна.

---

### 3. Порядок виконання

#### 3.1. Створення та розробка плагіна
1. Згенерувати шаблон плагіна за допомогою Flutter CLI (поза директорією вашого основного проєкту):
   ```bash
   flutter create --template=plugin --platforms=android,ios -a kotlin -i swift my_flashlight_plugin
   ```

2. У директорії `android/src/main/kotlin/...` реалізувати логіку роботи з `CameraManager`.
3. У директорії `lib/` налаштувати Dart-інтерфейс (статичний метод) для виклику нативного коду через `MethodChannel`.
4. Залити плагін у **новий, окремий репозиторій** на GitHub.

#### 3.2. Інтеграція в основний застосунок

1. Змерджити гілку Лаб. №6 у `main`.
2. Створити нову гілку `feature/lab-7-native` від актуального `main`.
3. Додати залежність у `pubspec.yaml` вашого основного проєкту:
```yaml
dependencies:
  my_flashlight_plugin:
    git:
      url: [https://github.com/your-username/my_flashlight_plugin.git](https://github.com/your-username/my_flashlight_plugin.git)

```


4. Реалізувати секретний тригер на UI для виклику `MyFlashlightPlugin.toggle()`.
5. Обробити виключення для платформи iOS / емуляторів.

---

### 4. Вимоги до звітності

1. **Pull Request (Основний застосунок):**
* Створити PR із гілки `feature/lab-7-native` у `main`.
* В описі PR **обов'язково** вказати посилання на репозиторій з вашим плагіном.


2. **Медіа-докази (Критично важливо):**
* Записати відео з реального Android-пристрою, де видно, як ви виконуєте секретну дію в застосунку і фізично вмикається ліхтарик.
* Записати друге відео (або додати до першого), де показано реакцію системи при запуску на iOS (чи емуляторі/вебі) — появу попереджувального діалогу без крашу.


3. **Код-рев'ю:** Проходження всіх перевірок лінтера в обох репозиторіях.

### 6. Вимоги до захисту (Контрольні питання)

Студент повинен продемонструвати розуміння низькорівневої роботи фреймворку:

1. **Platform Channels:** Детально пояснити архітектуру та відмінності між `MethodChannel` (для RPC-викликів) та `EventChannel` (для передачі потоків даних, наприклад, з акселерометра).
2. **Потоки (Threading):** На якому потоці (Thread) виконується нативний код, викликаний через `MethodChannel`? Як уникнути блокування UI-потоку в Android?
3. **Інтерфейси (FFI):** Що таке `dart:ffi` (Foreign Function Interface)? Коли доцільно використовувати `dart:ffi` (виклик C/C++ коду), а коли `MethodChannel` (виклик Java/Kotlin/Swift)?
4. **Hardware Lifecycle:** Як ваш плагін повинен поводитися, якщо застосунок згортається у фоновий режим (Background), а ліхтарик увімкнений?
