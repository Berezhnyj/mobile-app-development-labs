# :bookmark_tabs: Лабораторна робота №4
## Тема: "Інтеграція підсистеми авторизації та налаштування взаємодії з MQTT-пристроями"

### 1. Мета роботи
Реалізація повноцінного життєвого циклу сесії користувача, інтеграція мобільного застосунку з екосистемою Інтернету речей (IoT) через протокол MQTT та забезпечення стійкості (resilience) застосунку до змін стану мережевого з'єднання.

---

### 2. Завдання до лабораторної роботи

**Мета завдання:** Побудувати стабільний механізм аутентифікації з підтримкою автологіну, налаштувати підписку на потокові дані (Streams) від IoT-пристроїв через MQTT-брокер та реалізувати реакцію інтерфейсу на втрату інтернет-з'єднання.

**Функціональні вимоги:**
1. **Підсистема авторизації (Session Management):**
   - Повноцінна реєстрація та класичний вхід (Login) з валідацією.
   - **Автоматичне відновлення сесії (Auto-login):** При запуску застосунку система повинна перевіряти наявність збереженого токена/сесії у локальному сховищі і автоматично переспрямовувати користувача на головний екран, минаючи екран логіну.
   - **Безпечний вихід (Logout):** Завершення сесії з обов'язковим відображенням діалогового вікна підтвердження (Confirmation Dialog) для запобігання випадковому розлогіну.
2. **Модуль IoT (MQTT Integration):**
   - Підключення до публічного (наприклад, HiveMQ) або локального MQTT-брокера.
   - Підписка на визначений топік (наприклад, `sensor/temperature`).
   - Перехоплення повідомлень (payload) та їх декодування для відображення на UI.
   - *Симуляція:* Для генерації даних дозволяється використовувати фізичний мікроконтролер (ESP8266/ESP32), кастомний скрипт (Python/Node.js) або публічні веб-клієнти (MQTT Explorer).
3. **Моніторинг мережі (Network Awareness):**
   - **Блокування входу:** При спробі логіну без інтернету система повинна блокувати запит і виводити відповідне повідомлення (SnackBar/Dialog).
   - **Моніторинг у реальному часі:** Після входу система має слухати стан мережі. При втраті з'єднання відображати перманентне попередження (наприклад, червона плашка вгорі екрану).
   - **Офлайн автологін:** Якщо застосунок запускається без інтернету, але сесія існує, користувач допускається на головний екран, проте з жорстким попередженням про відсутність мережі (режим обмеженої функціональності).

**Архітектурні та інженерні обмеження (Acceptance Criteria):**
- **Ізоляція протоколів:** Логіка роботи з MQTT та перевірка стану мережі не повинна знаходитися безпосередньо у віджетах. Використовуйте сервісні класи або контролери.
- **Управління потоками (Streams):** Вхідні дані від MQTT та `connectivity_plus` є потоками. Вимагається їх коректна обробка через `StreamSubscription` з обов'язковим закриттям (`cancel()`) при знищенні об'єкта (`dispose()`), щоб уникнути витоків пам'яті (Memory Leaks).

#### 3.2. Референсний приклад MQTT-клієнта (потребує адаптації)
Цей код є базовим концептом. Ви повинні інтегрувати його у свою архітектуру, відокремивши логіку з UI-шару.

```dart
import 'package:mqtt_client/mqtt_client.dart';
import 'package:mqtt_client/mqtt_server_client.dart';

final client = MqttServerClient('broker.hivemq.com', 'flutter_client_id_123');

Future<void> connectAndListen() async {
  client.port = 1883;
  client.logging(on: false);
  client.keepAlivePeriod = 20;
  client.onDisconnected = () => print('Disconnected from broker');
  client.onConnected = () => print('Connected to broker');

  final connMessage = MqttConnectMessage()
      .withClientIdentifier('flutter_client_id_123') // Має бути унікальним
      .startClean()
      .withWillQos(MqttQos.atMostOnce);
  client.connectionMessage = connMessage;

  try {
    await client.connect();
  } catch (e) {
    print('Connection failed: $e');
    client.disconnect();
    return;
  }

  if (client.connectionStatus!.state == MqttConnectionState.connected) {
    print('MQTT Connected!');
    client.subscribe('sensor/temperature', MqttQos.atMostOnce);

    client.updates!.listen((List<MqttReceivedMessage<MqttMessage>> messages) {
      final recMess = messages[0].payload as MqttPublishMessage;
      final payload = MqttPublishPayload.bytesToStringAsString(recMess.payload.message);
      print('Received data: $payload');
      // TODO: Передати payload у State Management (наприклад, Provider/setState)
    });
  }
}

```

4. **Безпека:** Як і де безпечно зберігати сесії/токени користувача на мобільних пристроях?
5. **Архітектура (Research):** Пояснити, що таке `Provider` (або інший State Management) і навіщо він потрібен для управління даними, що постійно оновлюються (як-от від MQTT).
